# ThreeC 真实使用记录协议 v0.1

> 状态：**待执行**（协议已定义，**尚无任何真实记录**）。
> 目的：让 ThreeC 接受真实研究任务的检验，而不是继续扩大内部产物。
> ★★ 本文件**不预设任何正面结论**。执行结束时「ThreeC 有用」「ThreeC 没用」「无法判断」
> 三种结果都同等合法；**没有记录**也是一种结果，且不得被写成成功。

---

## 0 · 为什么需要这个协议

ThreeC 目前有：8 题材 / 33 事件的历史地图、1,300 条季节性模式、204 个当前窗口、84 条 PIT 角色、
62 个 Campaign。**但没有任何一条证据表明**这些产出改善过真实研究。

已知的三类风险，协议必须正面处理：

| 风险 | 具体形态 |
|---|---|
| **设计者偏差** | 作者本人既是工具作者又是唯一使用者 → 「原本不知道」的判断天然偏向工具 |
| **事后合理化** | 看到结果之后再回忆「当时我就觉得这条线索值得研究」 |
| **样本伪装** | 同一题材的 5 条线索被当成 5 个独立样本 |

---

## 1 · 要回答的问题（五项，逐条记录，不合并）

1. ThreeC 是否发现了**原本容易遗漏**的历史对应？
2. 是否改善了**研究方向筛选**或**历史证据覆盖**？
3. 是否减少了**搜集、核对、比较资料的时间**？
4. 哪些 **UI 或产物对实际判断没有帮助**（含「看起来有用但没被用过」）？
5. 哪些线索只是**已经知道的历史事实**，哪些确实带来了**新的研究增量**？

★ 问题 4 是**负向问题**，必须与 1–3 同等认真记录；只记正面条目会让整份日志失去价值。

---

## 2 · 记录规则（事件驱动，不是日历驱动）

### 2.1 何时记录

**事件驱动**：每当发生下列任一情况，就写一条记录（T 时刻冻结，见 §3）：

| 触发类型 | 说明 |
|---|---|
| `LEAD` | ThreeC 给出了一个作者此前未主动考虑的研究方向 / 历史对应 |
| `CONFIRM` | ThreeC 强化了作者已有的判断（**增量可能为零**，也要记） |
| `REJECT` | ThreeC 的产出让作者**放弃**了某个方向（负向价值，同样是价值） |
| `NO_LEAD` | 作者带着真实问题使用，但**没有**得到可用线索 |
| `BLOCKED` | 因数据缺失 / 口径不清 / 无法判断而中止 |
| `UI_FRICTION` | 某个页面或产物**没能帮上忙**（找不到、看不懂、读完仍无结论） |

★★ `NO_LEAD` / `BLOCKED` / `UI_FRICTION` **与 `LEAD` 同等重要**，且必须记录**触发量**：
本次使用中看了哪些页面、查了哪些题材、花了多久、为什么没产出。

### 2.2 观察期与数量

- **观察期**：**至少 2 周，最长 8 周**。到期即收口，不无限延长。
- **目标**：**≥10 条**实际产生的候选线索或研究观察记录（含负向类型）。
- ★ **数量不是硬指标，不得为凑数把同一条线索拆成多条**。
- 若观察期内线索很少或为零：记录
  - 实际**触发量**（打开过多少次、查过多少题材）
  - **符合条件的研究机会数**（期间实际出现了多少个「本可以用 ThreeC 研究」的问题）
  - **数据限制**（哪些问题因数据不足无法研究）
  - → 结论写「**触发不足 / 未观察到**」，**不得**写「工具无效」，**更不得**写「没有触发 = 成功」。

### 2.3 记录数量 ≠ 独立样本

- 同一**题材**、同一**事件**、或高度相关的线索（同一催化、同一板块、同一周内）→ 必须标
  `cluster_id`，并在汇总时**按 cluster 计数**，不得按条目数计。
- 汇总表必须同时给：**条目数** 与 **独立 cluster 数**。
- 一个 cluster 内的多条记录只能算 **1 个观察单位**。

## 3 · T 时刻冻结（本协议的核心机制）

★★ **必须在看到后续行情结果之前**冻结。冻结后**不得反向修改**当时写下的线索内容。

### 3.1 冻结字段（缺一项即视为该条记录无效）

| 字段 | 说明 |
|---|---|
| `record_id` | 唯一 ID，格式 `RU-<YYYYMMDD>-NN`（同日递增） |
| `frozen_at` | 记录时间（ISO 8601，含时分） |
| `data_as_of` | **当时实际行情截至日期**（从页面/产物读，不凭记忆） |
| `question` | 研究问题（一句话，可复核） |
| `background` | 触发这个问题的背景（新闻 / 财报 / 政策 / 盘面 / 他人提问） |
| `threec_output` | ThreeC 当时给出的**具体**线索：题材 / 事件 / 年份 / 参与标的 / 理由 / 来源链接 |
| `artifact_ref` | 输出文件版本 + 页面区块 + **可追溯 commit**（`git rev-parse HEAD` 或页面 Build Provenance） |
| `novelty_self` | 作者自评：**新颖 / 已知 / 不确定** + **理由**（★ 弱证据，见 §5） |
| `worth_researching` | 是否值得继续研究 + 理由 |
| `conventional_methods` | 当时是否有常规方法可用；**实际用了哪些**（Wind/Choice/研报/搜索/记忆） |
| `frozen_verdict` | `LEAD` / `CONFIRM` / `REJECT` / `NO_LEAD` / `BLOCKED` / `UI_FRICTION` |
| `cluster_id` | 关联簇（同题材/同事件/同催化共用） |

### 3.2 预留字段（**T 时刻留空，事后另行追加**）

| 字段 | 何时填 |
|---|---|
| `research_hours` | 研究结束后（含搜集/核对/比较的净耗时） |
| `new_correspondence` | 事后：是否真的发现了新的历史对应（有则写明是哪一条） |
| `false_alarm` | 事后：哪些提示被证明无效 |
| `evidence_quality` | 事后：证据等级（报道点名 / 盘面 / 仅推断 / 无法核实） |
| `outcome` | 事后：研究结论（成势 / 未成势 / 仍在进行 / 无法判断） |
| `evaluated_at` | 评估日期 |
| `evaluation_note` | 事后说明，**不得修改** §3.1 的任何字段 |

★ 追加时**只写 §3.2**；若确实需要更正 §3.1，必须新增 `amendments[]` 条目（写明原值、新值、
原因、时间），**不得静默覆盖**。

### 3.3 冻结的技术保证

- 记录文件放 `.tmp/real_use/records/`（**gitignored**，见 §6）。
- 每次冻结后立即 `git rev-parse HEAD` 写入 `artifact_ref.commit`，并在文件末尾追加该条的
  `sha256`（可用 `shasum -a 256`）→ 事后可证明「这一条在 T 时刻就是这样」。
- **不要求**把日志提交到仓库；冻结靠「本地只追加 + 哈希」即可。

## 4 · 外部独立参照（可选，本轮**不招募**）

目的：给「增量价值」一个**不依赖作者自评**的参照。**不是**用户调研，**不是**统计抽样。

### 4.1 流程

1. 选 1–3 个**有代表性**的研究任务（例如「2026 年冬季流感题材的历史对应」）。
2. 向参照者提供：**相同的研究问题 + 相同的数据截止日 + 必要背景**；
   ★ **不展示** ThreeC 的任何输出、截图、结论。
3. 参照者用**惯常工具**独立研究，并**先冻结**自己的线索清单（历史对应 + 来源 + 耗时）。
4. 双方都冻结后才比对，填四栏：
   - **共同发现**（两边都有）
   - **ThreeC 独有**（只有 ThreeC 给出，且参照者认可「这确实是个历史对应」）
   - **常规工具独有**（参照者找到而 ThreeC 没有 → **这是 ThreeC 的缺口**）
   - **无法核实**（双方都给不出可核来源）
5. 记录：双方研究耗时、覆盖的历史年份范围、来源质量、任务差异。

### 4.2 纪律

- ★ **1 个参照者 ≠ 有统计代表性的用户样本**。数量 < 5 时一律标 **`EXPLORATORY_CONTRAST`**，
  不得外推为「ThreeC 比常规方法好/差 X%」。
- ★ 不得**编造**参照者、访谈或结论。没有参照者就写「本轮未开展外部对照」。
- ★ 参照者的「常规工具独有」项必须逐条保留 —— 那是唯一能揭示 ThreeC 盲区的数据。

---

## 5 · 自评偏差的处置（★★ 关键）

作者的「原本不知道」判断**只能作为弱证据**，理由：

1. 作者**设计了**这些页面与产物 → 知道该往哪看；
2. 作者**编写了**历史事件库 → 「发现」可能只是「想起了自己写过的东西」；
3. 记忆不可靠 → 「我早就知道」与「我刚学到」在事后无法区分。

因此：

- `novelty_self` **不得**作为唯一的增量判据；
- 汇总时必须同时给出**至少一项**外部或客观参照：
  - 外部参照者对照（§4），或
  - **可核的时间证据**（例如：T 时刻的检索记录 / 笔记 / 对话历史，证明此前没查过该题材），或
  - **明确声明「本轮无外部参照，增量结论不成立」**。
- ★ 若三项都没有 → 结论只能写「**作者主观感受**」，不得写成「ThreeC 发现了新线索」。

## 6 · 日志存放位置（不公开）

实际记录**不进公开仓库**。已核实现有忽略规则：

```
.gitignore:26  .tmp/
.gitignore:9   *.local
```

→ 记录放 **`.tmp/real_use/`**（已被忽略），**不需要修改仓库忽略策略**。

```
.tmp/real_use/
├── records/            # 每条记录一个 md 或 jsonl（RU-YYYYMMDD-NN）
├── sessions.md         # 每次使用的触发量（打开哪些页面、查了什么、耗时）
└── summary.md          # 收口时的汇总（条目数 / cluster 数 / 正负分布）
```

★ 仓库内**只提交空白模板**（`docs/templates/`），**不提交任何真实记录**。
★ 若确需把脱敏后的样例提交，必须**显式标注 `SANITIZED_EXAMPLE` 且不含私人研究结论**。

---

## 7 · 收口判定（观察期结束时填）

观察期结束后，按下列顺序判定，**不得跳步**：

| 判定 | 条件 |
|---|---|
| **无法判断** | 有效记录 < 10 条，或独立 cluster < 5 → 只报告触发量与数据限制 |
| **有增量（待外部确认）** | 记录 ≥10 且 cluster ≥5，且至少 3 条 `LEAD` 经事后核实为「新的历史对应」，但**无外部参照** |
| **有增量（有外部对照）** | 同上，且 §4 已完成至少 1 次对照 |
| **无增量** | `LEAD` 类记录事后全部被证为「已知」或「无效」，且负向记录占多数 |

★★ 任何判定都**不得**表述为「ThreeC 已被验证有效」——本协议的样本量在设计上就**不足以**
支持这种结论。它只能回答「**在这位作者的这 N 次使用中，观察到了什么**」。
