## 2. 发现：3 处 Runbook 缺口

### 缺口 1（**已修**）· 观察必须关联对象，否则时间线永远为空

原 Runbook 步骤 4 只说「写观察」，**没说要填 `linked_object_id`**。
而 Lifecycle Tracking 完全依赖它 —— 不填，对象的生命周期**永远是空的**。

→ **已修**：步骤 4 补上「关联研究对象」小节 + 说明为什么重要 + L1/L3 的作用。

### 缺口 2（**已定：方案 B**）· 输入文件按 `snapshot_id` 命名

**本次实际踩到**：`observations/2026-10.json` 是**输入文件**。若为了加新观察而**就地追加**，
就会让**已签发的 `MS-2026-10-06-02` 失去可复现性**（用同一份输入重跑会得到不同的快照）。

**用户裁定：方案 B** —— 输入文件按 `snapshot_id` 命名，与产物**一一对应**：

```
market_regime/  MS-<snapshot_id>.json      observations/  MS-<snapshot_id>.json
```

**已实施并验证**（4 个 revision 各一对输入）：

| revision | regime | observations | 复现结果 |
|---|---|---|---|
| `MS-2026-09-15-01` | 全 `UNKNOWN` | 空 | **逐字节一致** |
| `MS-2026-10-06-01` | `FLAT`（媒体证据版，从 `bd92cae` 找回） | 5 条 | 数据内容一致 |
| `MS-2026-10-06-02` | `DOWN`（真实序列版） | 5 条 | 数据内容一致 |
| `MS-2026-10-06-03` | `DOWN` | 7 条 | 数据内容一致 |

> ★ **实施 B 时又挖出 2 个真缺陷**（见下），**均已修**。

### 缺口 2b（**已修**）· `--check` 把「生命周期状态」算进了内容一致性

`status` / `superseded_by` / `reviewed_by` / `reviewed_at` 由**签发 / 归档等后续事件**写入，
**不由输入决定**。把它们算进一致性，会让**任何已签发或已归档的快照永远无法复现** ——
那是**检查语义错了**，不是产物漂移。

→ **已修**：`--check` 改为**数据级**复现检查，并把差异显式打印出来
（`数据内容一致（可复现）；生命周期状态不同（磁盘 ARCHIVED / 重放 CANONICAL）`）。

### 缺口 2c（**已修**）· `reviewed_at` 取 `now` ⇒ 已签发快照不可复现

原实现 `reviewed_at = now`，且 `--check` 不重放签发信息 → **CANONICAL 快照必然复现失败**。

→ **已修**：新增 `--reviewed-at`，签发时间**必须可显式给定**（`--check` 时传入记录值）。

### 缺口 2d（**待定**）· `research_context` 未纳入输入文件

`research_context`（含 `research_question` / `known_limitations`）目前经**命令行参数**传入，
**未被任何输入文件捕获** → 它不在复现范围内（`--check` 会显式排除并说明）。

→ **待定**：是否把它也做成输入文件（`context/MS-<id>.json`），让「输入 → 产物」完全闭合？

### 缺口 3（**待定**）· Runbook 步骤 5 的命令不覆盖「修订」场景

现有命令示例只给了**首次装配**。而实践中只要改动 `market_regime` / `observations` / 研究对象，
就必须走**新 revision**（`CANONICAL` 不可变），需要额外传 `--snapshot-id` 与 `--supersedes`。

→ **待定**：把「修订流程」写进 Runbook（含「何时需要新 revision」的判定规则）。

## 3. 演练同时确认「有效」的部分

| 机制 | 实战表现 |
|---|---|
| **CANONICAL 门禁** | 生效；未签发内容默认不展示 |
| **`CANONICAL` 不可变 → 新 revision** | 生效；`02 → 03` 走通，`02` 自动 `ARCHIVED` + `superseded_by` |
| **append-only（L3）** | 生效；原 5 条观察**逐字未改**即通过 |
| **PIT 安全** | 生效；`asOf` 早于观察所在快照时看不到它们 |
| **diff 月度对照** | 生效；正确显示「观察 +2」而非被同日 revision 挤掉 |
| **索引自动重建** | 生效；4 份快照状态一致 |
