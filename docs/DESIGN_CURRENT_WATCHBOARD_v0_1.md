## ★★★ 补记（同日）：v0_1 的**数据来源错了**，已修正

用户追问「观察台是怎么来的」，把来源逐层查了一遍，**发现 v0_1 用错了字段**：

`current_candidates.json` 的元信息写明 ——
> `research_method`：**「阶段由产品端 Phase Evidence Matrix 独立推导，不由研究声明决定。」**

引擎 `PhaseInference` 也写明 ——
> `phase` = **推导阶段（权威值）**；`declared` = 研究声明的阶段；
> **「不一致时 UI 必须并列显示，不得静默取一」**。

**v0_1 直接读了研究侧声明的 `attention_state`，静默取了声明值。**

### 实测影响：6 个对象中 **2 个不一致**

| 对象 | **推导阶段（权威）** | 研究声明 | 命中规则 |
|---|---|---|---|
| `CC-2026-BCI-MEDTECH` 脑机接口 | **`UNKNOWN`** | `THEME_FORMING` | `R8_UNCLASSIFIED` |
| `CC-2026-AUTO-SMARTDRIVE` 智能驾驶 | **`UNKNOWN`** | `THEME_FORMING` | `R8_UNCLASSIFIED` |

其余 4 个一致（海上风电 `R6` / 算电协同 `R5` / 具身智能 `R4` / 光互联 `R4`）。

> ★★ **这个错误的后果恰好是我在下面反复警告的那一个**：
> v0_1 把两个「**证据组合不满足任何阶段规则**」的对象显示成「**主题形成**」——
> 而「主题形成」正是最容易被读成「还在早期、可能有机会」的标签。

### 修正后

- 阶段一律取 **`view.phase`（推导值）**，并**并列**显示 `declared`；
- **不一致时高亮**并写明「两者并列，不静默取一」；
- **「还缺哪些维度」改用引擎的 `missingDimensions`（八维矩阵）** —— 不再自算三维；
- 补上**命中规则 id + 说明**（任何阶段结论都能被追问「为什么」）；
- 补上**覆盖度**（`known/total`）与 `researchReady` / `similarityReady`。

### 顺带发现

- `oneLiner`（研究侧叙事原文）**含 markdown `**`**，其中一处是 2026-10-08 我为汽车候选写的。
  按全库既有约定（`DirectionLookupSection` 的做法）**渲染为加粗**，不丢弃、不字面显示。
- 引擎已算好 `missingDimensions` 与 `coverage` —— **产品侧不应另起一套**。v0_1 自算三维属于重复劳动且更弱。

## 〇、先说清楚一件事：**「可能性排序」不能做**，理由有三

用户要的是「提前看到**可能性较高**的主题」。我必须直接说明为什么这一版**不给可能性**：

| # | 理由 |
|---|---|
| 1 | **红线** —— `AGENTS.md` §1 明令禁止 **概率 / 胜率 / 推荐分 / 预测**。 |
| 2 | **样本极小** —— 当前研究对象只有 **6 个**，历史 **53 段**。任何「可能性」都**不可验证**。 |
| 3 | ★ **最要紧的一条** —— **一旦给出排序，它就会被当作推荐使用**，而项目明令禁止荐股。工具**无从阻止**这种读法，只能**不生产排序**。 |

> **这不是保守，是这套工具唯一站得住的做法。**
> 一个「可能性排行榜」，用户无法验证、作者无法负责，且它把「研究辅助」直接变成了「选股」。

## 一、但用户的诉求是**真实的**，而且**已被项目满足了一半**

> 「不是我自己一一去对照」—— 这句话点出了真问题：**信息存在，但没有被组织成一屏可读的形态。**

★ 关键事实：**研究侧已经在做「提前观察」了** —— 6 个当前研究对象就是它的产物。
每个对象都带：

| 字段 | 含义 |
|---|---|
| `attention_state` | **阶段**（封闭枚举：早期信号 / 主题形成 / 广泛确认 / 扩张 …） |
| `phase_window.start` | **阶段起点**（什么时候开始观察的） |
| `phase_evidence` | **三态证据**：广度 / 信息边际 / 叙事（初现 / 已现 / 强 / 未标注） |
| `narrative_types` | 叙事类型（POLICY_DRIVEN / TECH_BREAKTHROUGH / …） |
| `uncertainty_notes` | **未决问题**（研究侧自己列出的不确定处） |
| `research_questions` | 继续研究的入口 |
| `reference_cases` | 研究侧给出的历史参照 |

**缺的只是「把它们摆到一屏」** —— 这正是本产物做的事。

---

## 二、设计：**状态陈列**，不是**可能性排序**

### 2.1 三条纪律（写进代码与界面）

1. **按「阶段」分组**（封闭枚举），组序 = **生命周期自然序**；
2. 组内按 **`phase_window.start` 时间序** —— **不是价值序**；
3. **核心列是「还缺什么」** —— 把「提前观察」落到**下一步看什么**。

### 2.2 ★★ 「还缺什么」是这一版的关键

`phase_evidence` 的三个维度里，仍为 **初现 / 未标注** 的即为缺口：

```
CC-2026-BCI-MEDTECH   广度 初现 · 信息边际 初现 · 叙事 已现   → 还缺：广度 · 信息边际
CC-2026-EMBODIED-AI   广度 强   · 信息边际 已现 · 叙事 强     → 还缺：（无）
```

> **这一列直接回答「我现在该看什么」** —— 而「该看什么」是**研究问题**，
> 「该买什么」才是**荐股**。前者可以做，后者不能做。

### 2.3 界面文案（强制与表同显）

> 本表是研究侧**观察状态的陈列**：现在有哪几个方向在被观察、各自处在什么阶段、观察到什么、还缺什么。
> **阶段越早不等于越可能启动** —— 阶段是当前状态的分类，不是可能性；
> 本表按阶段分组（组内按阶段起点时间序），**不评分、不排名**，**非预测**。

★ 措辞沿用全库既定的否定式白名单（`不评分、不排名` / `非预测`），以免触发既有的评分词护栏。

---

## 三、为什么这不是「历史对照」的重复

前一轮实现的「启动前观察」是**历史侧**（某段历史启动前的量价）。
本产物是**当前侧**（现在有哪几个方向在被观察）。

两者**不能并列**（历史标的为事后选定，与当下比形态会系统性偏高 —— 见 `DESIGN_EARLY_OBSERVATION_v0_2.md`）。
本产物**只陈列当前状态**，不引用任何历史形态做比较。

---

## 四、刻意**不做**的事

- ❌ 不给「可能性 / 概率 / 优先级」排序
- ❌ 不评分、不打分、不给星级
- ❌ 不预测哪个会启动
- ❌ 不把「阶段早」渲染成「机会大」（声明里**明写**二者无关）
- ❌ 不新增研究结论（全部字段**原样透传**研究侧数据）

---

## 五、如果仍要更接近「提前看到」

在不越线的前提下，还能做的是**把观察做得更密**，而不是**把判断做得更早**：

| 可选 | 说明 |
|---|---|
| **增加当前研究对象** | 现在只有 6 个。用户想问的方向大概率不在里面 —— 这是**覆盖**问题，不是排序问题 |
| **提高证据层级** | 当前观察项多为 Tier 3（媒体转述）→ 补 T1/T2 一手来源 |
| **月度节奏** | 每次快照 diff：「这一期相比上一期，哪个对象的哪个维度变了」 —— **变化是事实**，比排序有用 |

> ★ 最后一条（**快照 diff**）正是 `PROJECT_STATE §7` 记的「唯一下一目标 1.2d」，一直没做。
