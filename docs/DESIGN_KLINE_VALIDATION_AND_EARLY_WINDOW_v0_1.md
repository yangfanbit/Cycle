## 一、问题 1：放宽素材标准 + 交叉信源 + K 线对照

### 1.1 可以放宽到什么程度（建议规则）

| 项 | 现规则 | **建议新规则** |
|---|---|---|
| 来源层级 | Tier 1/2 优先；Tier 3 仅转述 | **Tier 3 可作为独立证据**，但须满足下方交叉条件 |
| 交叉要求 | `independence_group` ≥2 | **不变**，且**必须跨类型**（不能两条都是同一事件的转述） |
| ★ **日期锚点** | 依赖来源文本 | **必须与 K 线对照**（见 1.3） |
| 空缺 | 合法状态 | **不变**（不编造仍是第一原则） |

**新增判定式**：一条证据若为 Tier 3，须满足
`≥2 个独立来源（不同 independence_group）` **且** `其日期锚点经 K 线可验证`。

### 1.2 交叉信源验证 —— 可机器化

- 已有 `independence_group` 字段（R01/R02 包已用）✓
- **新增检查**：同一 `independence_group` 内多条 → 视为 1 条
- **新增检查**：Tier 3 证据必须 `≥2 组` 才可作为**日期锚点**（否则只能作 `context`）

### 1.3 ★ K 线对照 —— 已做**概念验证**，有效

**做法**：用 campaign 的代表标的（`campaign_securities`）的真实 `adj_close`，
**客观计算** start / peak / end，与记录口径对照。

**实测三例**（今日跑通）：

| Campaign | 记录 peak | **K 线实测峰值** | 判定 |
|---|---|---|---|
| `C-2023-AD` | 2023-07-11 | **2023-07-13** | ✓ 差 2 日 |
| `C-2020-POWER-NE` | 2021-11-01 | **2021-10-27** | ✓ 差 5 日 |
| `C-2019-COMM-5G` | 2020-02-25 | **2020-07-14** | ⚠️ **差 4.5 个月** |

#### ★★ 第三例的差异**不是错误，是方法论问题**（必须记录）

```
C-2019-COMM-5G 的三只标的：
  EOPTOLINK  峰 2020-07-14 (+536%)   ← 主导了等权组合
  INNOLIGHT  峰 2020-02-24 (+153%)   ← 与记录一致
  ZTE        峰 2020-02-25 (+94%)    ← 与记录一致
```
**等权组合的峰值由「涨幅最大的那只」决定** —— 而记录口径显然用的是多数标的的峰值。

→ **结论：K 线对照必须显式规定「聚合口径」，并同时给出逐标的明细。**

**建议口径**（三选一，须明确声明）：
| 口径 | 含义 | 适用 |
|---|---|---|
| **逐标的** | 每个标的分列 peak | **默认**（最诚实，不掩盖分歧） |
| 中位数 | 各标的 peak 的**中位数** | 稳健，但会掩盖极端 |
| 等权组合 | 归一化后平均 | 易被极端标的带偏（本例即如此） |

### 1.4 ★ K 线对照的真正价值（比「验证」更大）

它**不只**用来核对既有日期 —— 它能让**日期锚点本身从「媒体转述」升级为「市场客观事实」** ✓。

> **这直接解决了 R02-02 的 DEFER 问题**：R02-02 被 DEFER 的原因是「**缺行情序列、peak 无法界定**」。
> **若补上 K 线，peak 可由行情客观界定** → 该候选可能从 DEFER 转为可入库。

## 二、问题 2：「提前观察窗口期」逻辑上能实现吗

### 2.1 结论：**能**，但必须先过**红线**这一关

### 2.2 ★★ 红线约束（决定性）

`AGENTS.md` §1 明令禁止：**概率 / 胜率 / 推荐分 / 预测**。

因此「提前观察窗口」**绝不能**做成：
> ❌ 「出现 X 形态后，N 日内上涨的概率是 P%」

**可以**做成（描述性对照）：
> ✅ 「这个历史 Campaign 在启动前 N 日，K 线上出现了什么」
> ✅ 「当前是否出现了类似形态」
> ✅ 两者**并列呈现**，**由用户自己判断**

### 2.3 可行的定义（**ex-ante**，非事后拟合）

关键：用的量必须是**当时就能算出来的**（不引入未来信息）。

| 观测量 | 定义 | 为什么可用 |
|---|---|---|
| **成交量分位** | 当日量在**过去 60 日**中的分位 | 只用历史数据 ✓ |
| **相对强度** | 标的收益 / 基准（SH000300）收益，滚动 20 日 | 只用历史数据 ✓ |
| **波动率变化** | 20 日波动率 / 60 日波动率 | 只用历史数据 ✓ |
| **价格结构** | 是否站上 20/60 日均线 | 只用历史数据 ✓ |

**对历史案例**：算出「启动前 N 日，上述量的取值」→ **描述事实**
**对当前**：算出同样口径 → **描述事实**
**并列呈现，不给概率、不给评分、不排序** ✓

### 2.4 为什么这是「可实现的」

- **数据**：`market_daily` 已有 open/high/low/close/adj_close/volume/amount ✓
- **基准**：`SH000300` 已在库 ✓（算相对强度必需）
- **历史案例的锚点**：`campaigns.start_date` ✓（且可用 K 线客观校验，见 §1.3）
- **纯离线计算**：不联网、不调 LLM，符合 Product 侧约束 ✓

### 2.5 但有两个必须先说清的边界

| 边界 | 说明 |
|---|---|
| **不是「预测」** | 它只说「历史上启动前长什么样」+「现在像不像」，**不说接下来会怎样** |
| **样本极小** | 13 个可对照 campaign（补 K 线后最多 53）—— **任何「规律」都极不稳健**，因此**尤其不能给概率** |

> ★ **正因为它像「预测」，才更要严格不做预测。** 描述与判断之间那条线，就是项目的红线。
