> 触发：使用者「补历史信息侧数据源」，承接 v0.85（`docs/HISTORICAL_REPLAY_FEASIBILITY_v0_2.md` §6）

> 而 `INSUFFICIENT_VARIATION`，当时判断瓶颈在「历史信息侧数据不足」。

## 0 · 实测先行：上轮建议被推翻的两处（必须先说清）

### 0.1 「回溯抓到 2014」做不到

v0.85 报告建议「按 `FRONTIER_CADENCE` 的采集纪律，把部委列表页回溯抓取到 2014」。
**实测（2026-11-15，逐页访问，非推断）**：

| 来源 | 分页机制 | 可取页数 | 最远日期 | 本轮状态 |
|---|---|---|---|---|
| `NDRC_ZCFB_TZ` 发改委·政策通知 | 首页 `createPageHTML(20, 0, "index", "html")` | 20（首页 + `index_1..19`） | **2021-02-08** | ✅ 全取，0 失败 |
| `NDRC_XWFB` 发改委·新闻发布 | 首页 `createPageHTML(40, 0, "index", "html")` | 40（首页 + `index_1..39`） | **2017-12-18** | ✅ 全取，0 失败 |
| `NHSA_NOTICE` 医保局 | jpage `totalRecord=361 / perPage=15`，`dataproxy.jsp` 需会话态 | 0 | — | ❌ 接口返回 54 B 空响应，逐次记录 |
| `NEA_XNY` 能源局 | `index_N.htm` 返回 ~24 KB 但 **0 条可解析条目**（空壳页） | 0 | — | ❌ 逐页记录 |
| `MIIT_KJS` 工信部 | 无 `index_N.html` | 0 | — | ❌ 无历史分页 |

→ **公开列表页最远只到 2017-12-18，不是 2014**。网站只保留 20 / 40 页，这是数据边界，
不补造、不用其他来源假装补齐。60 页共 **1,274 条**去重后可核文件，逐年 92–238 条。

### 0.2 瓶颈不只是「数据条数」，更是「可核的板块关联」

对 1,274 条标题做实测（未调任何阈值）：

| 映射方式 | 命中标题 | 覆盖板块序列 |
|---|---|---|
| v0.82 已发布 15 词表（DIRECT / PROXY，带 rationale） | **12** | 4 |
| 库内 317 个可解释板块名称的精确自匹配 | **25** | 10 |

发改委新闻发布标题以宏观政策为主（「关于…的通知」「…情况」），产业专指性低。
★ 更硬的结构性约束：v0.85 的映射表只覆盖 **12 / 399 = 3.0%** 序列，
`F3 = NO_COVERAGE` 对另外 385 个序列恒成立 → 即使历史文件 **100% 命中**，
`F3=1` 的上限也只是 `12 × 49 / 15,474 = 3.8% < 5%`。
**主口径 C1 在设计阶段即可判定不可能达标**，与抓多少条无关。

→ 本轮不把「让 C1 达标」当目标；目标改为 **① 落盘真实可核的历史信息资产，
② 量化覆盖率改善，③ 用敏感性对照定位剩余瓶颈，④ 如实判定③层状态**。

## 1 · 数据资产口径

### 1.1 产物
`research/current/historical_info_events_v0_1.json`（新文件，不覆盖雷达 v0_10 等既有产物）。
脚本 `research/scripts/build_historical_info_events_v0_1.py`，模式 `--fetch --write` / `--check`。

### 1.2 每条事件字段（全部可核）
`event_id`（由 `source_id + date + URL` 确定性哈希）、`source_id`、`publisher`、
`title`、`url`、`event_date`、`date_source`、`page`、`fetched_at`、
`title_sha256_16`、`mapping`（见 §3）。

★ **日期口径**（沿用项目纪律）：列表日 ≠ 成文日 ≠ URL 路径日期。
事件日期一律取**列表页上网日**，`date_source = LIST_PAGE`；
医保局如后续接入则记 `URL_PATH`。**不得用正文 PubDate 冒充首次公开时间**
（`NEA_XNY` 实测 51/111 条 PubDate 是成文日，最多早 179 天）。

### 1.3 缺口逐来源写原因，不静默丢弃
产物必须给 `source_coverage[]`：每来源的 `pages_requested / pages_ok / items / date_min / date_max /
status / gap_reason`。`NO_HISTORICAL_PAGINATION`、`PROXY_EMPTY_RESPONSE`、
`EMPTY_SHELL_PAGE` 三类分别计数并写含义；失败页逐页登记。

### 1.4 联网与确定性
- `--fetch` 才联网，节流 ≥1.1 s/页，沿用雷达脚本的研究型 UA 与 `Referer`；
- `--check` **绝不联网**（CI 只读）：只校验产物内部一致性、页级指纹、覆盖守恒、
  映射双向校验、禁用措辞；产物缺页时显式 SKIP 并打印范围；
- 抓取是快照，产物记 `fetched_at` 与每页 `html_sha256_16`；
  **重新抓取必须升版本**，不得原地覆盖 v0.1。

## 2 · PIT 与「事后检索」声明（诚实边界）

★ 用 **2026 年构建的词表**去检索 2017–2026 的历史标题，是**事后检索（post-hoc）**：
当时的研究者不一定持有这份词表，也不一定用同样方式关联板块。
因此产物必须显式写：

- `lexicon_is_post_hoc = true`、`lexicon_built_at = 2026-11-15`；
- `not_point_in_time_signal = true` —— 本数据只用于**历史描述统计与特征可用性评估**，
  **不得解读为当时投资者可得的信号**，不得用于任何实盘口径；
- 保守可用时点：事件日当天**不计入**反应（沿用 `FRONTIER_CADENCE` 纪律），
  特征回看窗口 `T-365 自然日` 且严格 `event_date <= T`；
- 词表版本化：对每个关键词登记 `first_verifiable_mention_year`
  （从本轮 1,274 条标题里可核的首次出现年份；无命中写 `null` 并标 `NO_OBSERVED_MENTION`，
  **不用外部知识猜年份**）。这只是弱证据，不用来裁剪历史、不改变词表。

★ 板块历史成分 `ACCESS_GATED` 未解：本轮**不做**成分级回填，
不得用当前成分名单冒充历史成分（`AGENTS.md` 与 `MEMORY_DETAIL` 明令）。

## 3 · 映射表分层（不硬贴，双向校验）

| 层 | 词表 | 目标序列数 | relation | 用途 |
|---|---|---|---|---|
| L1 严格 | v0.82 已发布 `KEYWORD_MAP`（15 词，逐词带 rationale） | 12 | DIRECT / PROXY | **主口径**，与 v0.85 可比 |
| L2 历史角色 | v0.85 `ROLE_MAP`（5 个 theme，显式标 PROXY） | 5（与 L1 有重叠） | DIRECT / PROXY | **主口径**，与 v0.85 可比 |
| L3 名称自匹配 | 库内 `interpretable=true` 的板块/篮子**名称本身**（≥3 字） | ~317 | `NAME_MATCH_ONLY` | **仅敏感性对照**，不进主口径、不进③层判定 |

- L3 每条带 `evidence_grade = WEAK`、`reason = "板块名称逐字出现于标题，仅作检索线索"`，
  明确**不等于**「该事件关联该板块」；
- 三层都在 `--check` 里做**构建时双向校验**：每个目标 `board_series` 必须在 `scan_series`
  里真实存在，否则整体 FAIL；未通过的词写入 `dropped[]` 并计数，不静默丢；
- 中文词边界：L3 用逐字包含但要求关键词长度 ≥3 且排除通用词表
  （`关于 / 通知 / 工作 / 情况 / 发展 / 建设 / 管理 / 政策 / 有关 / 印发 / 国家 / 问题 / 意见 / 加强 / 推进 / 开展 / 组织 / 实施 / 部门 / 全国`），
  避免「电力市场」类泛化词把宏观文件全命中；排除词表本身写进产物；
- **禁止**公司名子串匹配、正文关联、模糊相似、用板块分类体系反推事件归属。

### 6.1 禁用措辞扫描范围（实现细化，冻结时一并写定）

★ 禁用措辞扫描**只覆盖本脚本生成的说明性字段**（`purpose` / `limits` / `pit_note` /
`date_rule` / `gap_legend` / `gap_reason` / `note` / `reason` / `rationale` 等）。
`events[].title`、`events[].url`、`mapping_hits[].title` 是**外来原文，逐字保留**，
不参与扫描：实测真实标题「国家完善新疆棉花**目标价格**政策」含「目标价」三字，
属形状误判；为过检查而改写原文标题等于篡改数据。扫描范围写进产物并由 `--check` 断言。
★ 事件 URL 允许 `http` 与 `https` 两种 scheme（实测 2 条 `http://www.china.com.cn` 外链），
产物按 scheme 分布如实披露；`--check` 只要求 `https?://` 开头且 host 非空，
不把 http 外链静默丢弃或伪装成 https。
