## 4. ★★★ 但随之暴露一个更重要的问题

查「谁匹配了谁」时发现：

| 历史对象 | 被几个当前方向当作唯一结构支持 |
|---|---|
| **`C-2023-AD`（智能驾驶）** | **4 个** ← 脑机接口 · 人形机器人 · 智能驾驶合规化 · 文化传媒 |
| `C-2023-COMM-OPTICAL` | 1 个（光互联） |
| `C-2025-ROBOTAXI` | 1 个（光互联） |

### 量化「通用性」——结论与直觉相反

| 驱动 | 历史对象频次 |
|---|---|
| `POLICY_DRIVEN` | **37 / 79（47%）** |
| `TECH_BREAKTHROUGH` | **8 / 79（10%）** |
| **两者同时** | **3 / 79（4%）** |

> ★ **历史侧其实并不通用** —— 同时具备「政策 + 技术」的只有 **4%**。
> **问题在当前侧**：4 个方向共享**同一个结构画像**
> （`POLICY_DRIVEN + TECH_BREAKTHROUGH` + `THEME_FORMING`）。

**这意味着**：
- 「**哪个历史对象**」这个信息量**低**（4 个方向都指向同一个）
- 「**属于哪一类结构**」这个信息量**高**（都属「政策驱动 + 技术突破 + 主题形成期」）

**并且它本身是个研究结论**：这 4 个方向在**结构上是同一类** —— 这解释了为什么它们会**同期**出现在研究视野里。

## 5. ★ 产品级缺口（本轮真正的产出）

### 缺口 A：方向查询说「未覆盖」就停了

现在 `directionLookup` 对文化传媒返回 `none`，文案是「本工具**未覆盖**该方向」。
**但这句话对「主题名」成立，对「结构」不成立** —— 沙箱证明结构层面**能给出答案**。

→ **产品应当区分这两种「没有」**：
- 「**主题名**未覆盖」≠「**结构上**无对应」
- 后者才意味着工具真的帮不上

### 缺口 B：同一个历史对象匹配多个方向，用户看不到

用户看到「文化传媒 ↔ 智能驾驶 结构支持」，会以为找到了**专属**对应。
**实际上那个人形机器人 / 脑机接口 / 智能驾驶合规化也都指向它。**

→ 应当暴露**该对应的特异性**（例如「此历史对象同时是另外 3 个方向的对应」），
**否则用户会高估这条对应的信息量**。

> ★ 这不是「分数」，是**计数事实** —— 不违反任何红线。
