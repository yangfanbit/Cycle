# 真实使用记录 · 轻量协议 v0.1（2026-11-04 生效）

> 取代 `THREEC_REAL_USE_PROTOCOL_v0_1.md` 的 **12 通用 + 1 条件字段**流程。
> 那份协议的 T 时刻冻结、cluster 计数、外部参照、负向类型等**方法论全部保留**，
> 砍掉的是**记录成本**：对「作者本人即唯一使用者」的单人场景，
> 逐条填 13 个字段 + 外置 SHA 会让记录成本高于研究本身 —— 实测协议定义至今 **0 条记录**。
> 原协议文件保留，作为完整方法论参考；**日常记录以本文件为准**。

---

## 1 · 记什么（3 个手填字段）

| 字段 | 内容 | 要求 |
|---|---|---|
| `question` | 一句话研究问题 | 可复核，不写「随便看看」 |
| `verdict_at_T` | **T 时刻**的判断：这条线索是什么、我此前是否考虑过、准备做什么 | 看到后续行情/结果**之前**写下 |
| `posthoc_check` | 事后核对：结论是否成立、是否为新的历史对应、有没有原本没查到的对应 | **另存**，不改 `verdict_at_T` |

自动字段（不用手填）：`record_id`（`RU-YYYYMMDD-NN`）、`frozen_at`（ISO 8601 含时分）、
`data_as_of`（当时页面/产物的行情截止日）、`type`、`cluster_id`（可空）、`artifact_ref`（当时 HEAD）。

**`type`（六类，负向同等重要）**：`LEAD` / `CONFIRM` / `REJECT` / `NO_LEAD` /
`BLOCKED` / `UI_FRICTION`。
`CONFIRM` 的增量可能为 0，也要记；`NO_LEAD` / `BLOCKED` / `UI_FRICTION` 必须写**触发量**
（看了哪些页、查了哪些题材、花多久、为什么没产出）。

---

## 2 · 纪律（从原协议继承，不打折）

- **T 时刻冻结**：正文写完后不改；需要更正就新建 `amend-NN`，不覆盖原记录。
- **事后分离**：`posthoc_check` 是独立字段/独立文件，与正文物理分开（工作台 UI 上也是两个区）。
- **cluster 计数**：同一题材 / 事件 / 同一周内的相关线索共用一个 `cluster_id`；
  汇总同时给「条目数」和「独立 cluster 数」，**按 cluster 计观察单位**。
- **自评偏差**：作者的「原本不知道」只是弱证据。若无外部参照或可核时间证据，
  结论只能写「作者主观感受」，不得写「ThreeC 发现了新线索」。
- **外部参照**（可选）：1–3 人独立研究同一问题并先冻结自己的线索清单，再比对四栏；
  < 5 人一律标 `EXPLORATORY_CONTRAST`，本轮不招募。
- **不得编造**：没有记录就写「本轮未开展」；「没有触发」≠「工具无效」≠「成功」。

---

## 3 · 存放与触发

- 工作台把记录存在浏览器 `localStorage`，可**导出 JSON**；
  导出文件放 `.tmp/real_use/records/`（已被 `.gitignore` 忽略，**不入库**）。
- 仓库内只有空白模板与方法论文档，**不放真实研究结论**。
- **事件驱动**（不是日历驱动）：发生上述任一 `type` 就记一条。
- 观察期 **2–8 周**，到期即收口，不无限延长。
- 目标 ≥10 条记录 / ≥5 个 cluster；**数量不是硬指标，不得拆条目凑数**。

## 4 · 收口

按 `docs/EVALUATION_FRAMEWORK_v0_1.md` §5 与**事前冻结的**
`docs/REAL_USE_DECISION_RULE_v0_1.md` 判定：先报触发量与负向记录，
再判断是否有**可核的新线索**、是否省了时间、有哪些盲区，最后才决定是否派发开发任务。
**在 C（真实使用）产生记录之前，不以「功能还不够」为由启动新一轮开发。**

纪律约束的是「以功能不足为借口的自动派发」，不否定使用者本人的授权，
也**不改变「有效性未验证」这一结论**。
