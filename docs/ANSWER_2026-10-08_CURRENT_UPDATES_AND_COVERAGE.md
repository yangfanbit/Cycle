## 一、状态记录于 09-15，以后如何更新？

### 1.1 机制**已存在**（脚本 + 校验 + diff + manifest）

`research/scripts/refresh_current_research.py` 是刷新循环的**唯一入口**：

```
python research/scripts/refresh_current_research.py --check                    # Temporal Firewall 校验
python research/scripts/refresh_current_research.py --diff --baseline <旧快照>  # 与基线做 candidate diff
python research/scripts/refresh_current_research.py --write-canonical          # 显式写入
python research/scripts/refresh_current_research.py --check --record           # 记录 manifest
```

★ **关键约束**：脚本**不做研究判断** ——
`current_candidates.json` **只在显式 `--write-canonical` 时写入**，且内容**必须已由离线研究准备好**。
也就是说：**脚本不会让内容变新，它只把已经准备好的内容安全地落盘。**

### 1.2 现状：**三层数据不同步，且候选层最旧**

| 数据 | 快照日 | 距今（2026-10-08） |
|---|---|---|
| `current_candidates.json`（研究对象） | **2026-09-15** | **滞后 23 天** |
| `market_regime`（市场环境） | 2026-10-06 | 2 天 |
| `observations`（观察项） | 2026-10-06 | 2 天 |
| 快照 revision 10（装配产物） | 2026-10-06 | 2 天 |

★ 产品**已有**滞后提示（`SNAPSHOT_STALE_THRESHOLD_DAYS = 14`，
`CurrentCandidateSection` 会显示「距今天 N 天」+「不是实时研究结果」）。
**但没有任何地方提示「候选层比环境层旧 21 天」。**

### 1.3 缺的是什么

| 缺口 | 说明 | 出处 |
|---|---|---|
| **月度研究流程**（checklist + 半自动脚本） | regime 填报 → 候选更新 → 快照装配 → 校验 → diff | `PROJECT_STATE §7` 的 **1.2e**，未做 |
| **四层 diff**（环境 / 对象 / 候选 / 观察） | 现有 diff 只到 **candidate 级** | `PROJECT_STATE §7` 的 **1.2d**，未做 |
| **层间时间一致性检查** | 本次新发现：候选层与另两层可差 21 天而无人报警 | 本文 |

> **结论**：更新**不会自己发生**。每轮需要有人（或 AI）**离线产出新的候选内容**，
> 再走 `--check → --diff → --write-canonical → --record`。
> **当前已滞后 23 天，且没有任何流程提示该更新了。**

## 三、哪些主题时间集中度最显著？→ **已加标注**

### 3.1 先说发现：地图**原本已有**「集中 X–Y」，但**没说有多少个真的落在那里**

`SeasonalMap` 早已显示 `· 集中 MM-DD–MM-DD`（`consensus` 中位窗口）。
问题：**资源（3/4）与汽车（6/6）看起来一样** —— 缺的是**计数**。

### 3.2 实测：12 个主题的年内集中度

| 主题 | 年内窗口 | 落在最集中区间 | 区间 | 标注 |
|---|---|---|---|---|
| **汽车** | **6** | **6** | **05-23 ~ 07-23** | ✅ |
| **资源** | 4 | 3 | 03-02 ~ 05-02 | ✅ |
| **金融** | 4 | 3 | 09-25 ~ 11-25 | ✅ |
| 电子 | 6 | 2 | — | ✗ 分散 |
| 消费 | 4 | 2 | — | ✗ |
| 高端装备 | 4 | 2 | — | ✗ |
| 国防军工 | 2 | 2 | — | ✗ 样本不足 |
| 房地产 / 信息通信 / 医药健康 / 未标注 | ≤2 | — | — | ✗ 样本不足 |

**★ 汽车是唯一「6 个年度窗口全部落在两个月内」且横跨 6 年的主题**：

```
2020-06-11 ~ 07-13    2021-06-01 ~ 08-06    2022-05-23 ~ 06-28
2023-07-03 ~ 07-19    2024-07-11 ~ 07-29    2025-06-22 ~ 06-24
```

### 3.3 实现（`themeSeasonality.ts` + 地图标注）

- **判据**：常规窗口 ≥ **3** 且最集中的两个月覆盖 ≥ **2/3**
- **输出**：`年内窗口 6 个 · 其中 6 个落在 05-23 ~ 07-23` —— **纯计数**
- **标记**：达到判据者加「年内集中」小标记（3 个：汽车 / 资源 / 金融）
- ★ **不输出**强度 / 评分 / 等级；**不声称**「明年也会」
- 语义边界与标注**同显**：
  > 「年内窗口 N 个 · 其中 M 个落在某区间」是**历史计数事实**，不是概率、不是胜率、不是预测；
  > 也不代表该主题**明年**仍会在同一区间出现。
